# API Development

## 適用範囲

以下のタスクのみ適用する

- 詳細設計書に基づく新規API開発

以下には適用しない。

- フロントエンド全般
- 単純なバグ修正
- テストのみの作成
- ドキュメントのみの作成
- API以外の実装
- 調査・レビューのみの依頼



↓ここからおおざっぱにskill内容を記載。codex君これをもとにSKILL.mdとして正しく依頼できる文章に書き直して！

## 全体ルール

詳細設計書の作成から実装・テスト・修正・完了までを自動で行う。

修正可能な範囲でループして修正、完了までもっていく。

各ディレクトリのAGENTS.mdの方針に従い作業を進める。

逆に、以下は行わない。

- 仕様があいまいなところの勝手な推論での仕様確定
- 詳細設計書に対象外の範囲の勝手な変更

### 詳細設計

docs/design/backend/detail

- 開発者が大まかな仕様（雑な処理フロー、命名・ディレクトリ・関数使用ルール、大まかな規約）を策定した状態でスタート。詳細設計を策定する上での判断材料が詳細設計書及び基本設計書になければこの時点でストップ。
- 大まかな仕様とAGENTS.mdに記載のルールに従い詳細設計書を策定
- server/src以下のAGENTS.mdやdocs/codingRule/backend以下のコーディング規約に反する設計がある場合は、規約に合わせた仕様変更をしても問題なければ設計修正、少しでもあいまいな場合はストップ。

### 本番コード実装

server/src

- 詳細設計書に記載のとおりに実装
- 実装中に仕様があいまいな個所を発見したらストップ
- 関係ない箇所のエラーにより進行不能になれば、docs/todoに問題記載の上でストップ。

### テスト設計書作成

server/test/docs/architecture

- 詳細設計書と本番コードに基づき、テストの詳細設計を作成
- テスト未実行範囲、軽微な仕様不確定事項も記載
- 問題発生や仕様不確定によりテスト実行できない場合はストップ

### テストコード実装

- 単体テスト: server/src/（各ディレクトリ）/test
- 結合テスト: server/test/integration
- fixture: server/test/fixtures

- テスト設計書に基づき単体テスト、結合テスト、fixtureを実装

### テスト実行・レポート・修正案

server/test/docs/report

- 実装したテストを実行
- テスト設計書に対応するレポートを作成
- 失敗・ロジックの誤り・未実行があれば修正案を記入
- 仕様あるいは対象外範囲のエラーにより自動で修正できない場合はストップ

### 本番コード修正～テストコード修正～修正テスト実行～再修正～ループ

- テストレポートの修正案に基づき、修正可能な範囲で修正、テスト、再修正のループを完了まで回す
- 仕様あるいは対象外範囲のエラーにより自動で修正できない場合はストップ

### 完了

- 完了したら終了
