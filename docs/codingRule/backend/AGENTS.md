# Backend コーディング規約作成ルール

## 対象と目的

このファイルは `/docs/codingRule/backend` 配下の Markdown を作成・更新する作業に適用する。

このディレクトリは、バックエンド実装で**必ず守るコーディング規約**を定義する場所である。単なる推奨、参考情報、実装例のメモを記載する場所ではない。

各 Markdown は、対応するバックエンドの責務・ディレクトリにおける必須ルールとして扱う。規約と実装が矛盾する場合、実装者は規約を優先しなければならない。

## 作成・更新時の必須手順

規約を追加または更新する前に、以下を必ず確認する。

1. このディレクトリ内の既存規約
2. 対象ディレクトリの `AGENTS.md` と、上位ディレクトリの `AGENTS.md`
3. 対象ディレクトリの既存実装
4. 関連する層・ディレクトリの規約

既存の規約と矛盾するルールを追加してはならない。矛盾の可能性を解消できない場合は、推測で規約を作成・変更せず、確認が必要な点を報告する。

## 記述する内容

- 対象の責務と、実装で必ず守る制約を明確に記述する。
- 要件は「必ず」「禁止」「〜しない」など、遵守の要否が曖昧にならない表現で記述する。
- ルールが適用される条件、記述順、命名、型、安全性、エラー処理、他層との境界を必要に応じて定義する。
- 既存実装に複数の書き方がある場合は、採用する書き方と適用条件を明示する。
- 正しい記述例を示す場合は、ルールを補足する最小限の例にする。
- 禁止事項を示す場合は、必要に応じて禁止例と正しい代替を併記する。

## 記述してはいけない内容

- 「推奨」「必要に応じて」「原則」「基本的には」など、必須かどうかを曖昧にする表現
- 一時的な作業手順、調査メモ、未確定の設計案
- 特定の機能だけに閉じた仕様や、その場しのぎの例外
- 規約化の根拠が確認できない推測上のルール
- 上位の `AGENTS.md`、既存の規約、または関連層の責務分離に反する内容

例外を認める必要がある場合は、例外が適用される条件と、例外時に守るべき制約を必ず明記する。

## ファイルの作り方

- 規約は責務または対象ディレクトリごとに Markdown ファイルを分ける。
- ファイル名は対象の責務を表す小文字の英単語を使用する。既存の命名規則に合わせる。
- 新しい規約ファイルには、少なくとも `基本方針`、`ファイル構成`、各必須ルールの見出しを設ける。
- 見出しの粒度と書式は、既存の `model.md`、`route.md`、`controller.md` に合わせる。
- 実装の変更は行わない。規約の追加・更新に必要な Markdown ファイルだけを変更する。

## 規約の優先順位

ルールが競合する場合は、より対象に近い規約を優先する。

1. 対象ディレクトリの `AGENTS.md`
2. このディレクトリ内の対象責務のコーディング規約
3. `/server` 配下の `AGENTS.md`
4. リポジトリルートの `AGENTS.md`

ただし、下位規約で上位規約のセキュリティ、アーキテクチャ、スコープ管理の要件を緩和してはならない。

## 完了前の確認

- すべての記述が必須ルールまたは明示された例外になっていること
- 既存規約・対象実装・関連 `AGENTS.md` と矛盾しないこと
- 実装者が追加の解釈をせずに従える具体性があること
- 規約の対象外となる実装やファイルを変更していないこと
