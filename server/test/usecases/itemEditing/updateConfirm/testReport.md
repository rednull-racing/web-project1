### モックと外部アクセス

- モックはすべてVitestの `vi.mock`、`vi.fn`、`vi.spyOn` を使用。
- DB service/モデルとAWS署名の境界をモックし、DB作成・接続・マイグレーション・実S3操作は行っていない。
- Routerはテスト用Expressアプリに明示的にマウント。SupertestのローカルHTTP接続だけを使用する。
- 認証はテストごとに生成した鍵と実JWTを使用し、dotenvをモック。実環境の認証情報は使用しない。
- Routerのエラーはテスト専用4引数middlewareで観測。実アプリのRouter登録状態や共通errorHandlerの動作を検証したことにはしない。
- レート制限は実装を使用し、モジュールを再読み込みしてストアを分離。Dateとintervalのみfake timerで制御し、HTTP I/Oは実行する。
- 並行テストはdeferred Promiseで開始・完了順を制御。任意のsleepや実時間待ちには依存しない。

## 観測結果の詳細

### 商品画像署名の欠落（S13 / P06 / O03）

S3署名を個別のdeferred Promiseに置換し、同じ入力で完了順だけを変更した。返却配列の元indexとURL、件数をassertしている。

| 新規画像のindex | 署名の完了順 | 返却された署名のindex | 観測 |
| --- | --- | --- | --- |
| 0, 1, 2 | 0 → 1 → 2 | 0, 1, 2 | 欠落なし |
| 0, 1, 2 | 2 → 1 → 0 | 0, 1 | index 2が欠落 |
| 0, 1, 2 | 1 → 0 → 2 | 0, 2 | index 1が欠落 |
| 1 | 1 | 1 | 元indexを保持 |
| 0, 2 | 2 → 0 | 0 | index 2が欠落 |
| 1, 3 | 3 → 1 | 3, 1 | 欠落なし、返却順は入力順と異なる |

いずれも保存用の `finalImageUrls` は入力順で生成された。署名配列は元indexへの代入とfilterによる詰め直しを繰り返すため、後の代入で先に完了した署名を上書きする現行動作を再現できた。今回のテストはこの観測結果を明示的に記録するもので、既存コードの修正は行っていない。

### ブランド解決・別名作成（O02 / T05 / Q03 / P05）

- ID指定で存在するブランド、またはbrand付きaliasは採用される。
- 名前検索で見つかったブランド、新しく作成したaliasは戻り値へ採用されない経路があることを確認した。
- 未紐付けaliasがあっても別名作成へ進む。逐次2回実行でも、両方の名前検索を未登録で揃えた並行実行でも、作成serviceが2回呼ばれた。
- 別名作成は商品transaction開始前に呼ばれ、transaction引数も受け取らない。商品更新の失敗後に別名が実DBに残るか、unique制約があるかは未検証。

### 空画像・キー共有（O01 / O04）

- `finalImageUrls=[]` ではITEM_IMAGE_NULLにならず、先頭画像にundefined、画像保存に空配列を渡した。旧先頭画像が残るかどうかはDB待ち。
- 同じ商品を同一ミリ秒に再実行すると、各メディアのキーが一致した。
- 属性のuiIdが重複すると同じキーを使い、後で完了した署名が辞書を上書きした。uiId一意性やアップロード結果は保証していない。
